# oracle-snatch

Oracle Cloud の公式 API に無料の ARM インスタンス（VM.Standard.A1.Flex）の申請を繰り返し送り、在庫が放出されたタイミングで API が許可するまで粘る、小さな Python ループスクリプトです。

## なぜ作ったか

Always Free の A1.Flex 無料枠（合計 4 コア / 24 GB）は、現時点で一番お得な無料サーバーだと本気で思っています。問題は、人気リージョンではコンソールがほぼ常に「Out of host capacity（在庫なし）」と表示することです。この在庫は永遠にないわけではなく、不定期に少しずつ放出されます。ただし誰も知らせてくれません。コンソールを 1 週間更新し続けるのは人生の無駄です。聞きに行く役はスクリプトに任せましょう。

2026 年 10 月、私はこのループの粗い版を東京リージョンで数日間走らせました。ログは「在庫なし」の繰り返しで、間隔を攻めすぎて 429 のレート制限も何回か食らいました。それでも最後に 4 コア / 24 GB のマシンを確保できました。今はセルフホストしているサービスの大部分がその上で動き、請求は今日まで 0 のままです。このリポジトリは、そのループを整理し、設定を全部ファイルに外出ししたものです。

## 何をするか

- Oracle 公式 API（Python の `oci` SDK）だけを使います。コンソールの自動操作やブラウザの模倣はしません。
- リージョン内のすべての可用性ドメイン（AD）を巡回し、1 ラウンドにつき各 AD 1 回ずつ試します。東京は AD が 1 つだけですが、AD の多いリージョンの方が当選率は上がります。
- 「在庫なし」は「まだその時ではない」として扱い、少し待って次の AD、次のラウンドへ進みます。
- 429 に当たったら長めにバックオフします（デフォルト 300 秒）。レート制限に突っ込み続けると、制限が長引くだけです。
- クォータエラー（LimitExceeded）が出たら停止し、理由を明示します。無料枠を使い切っているので、1 万回リトライしても結果は変わりません。
- 確保できたらインスタンスが RUNNING になるのを待ち、パブリック IP を取得して `snatched.json` に書き、必要なら Telegram 通知を送って終了します。
- `--dry-run` は設定の検証だけを行います。AD の一覧と使うイメージを確認し、実際には起動しません。最初は必ずこれを実行してください。

しないこと：アカウント登録、VCN の作成、API キーの生成はしませんし、存在しない在庫を生み出すこともできません。ただ疲れを知らずに、あなたの代わりに聞き続けるだけです。

## インストールと使い方

Oracle Cloud アカウントと、API キーを設定した OCI 設定ファイル（`~/.oci/config`）が必要です。OCI CLI や SDK を使ったことがある人なら、すでに持っているファイルです。

サブネットの OCID も必要です。コンソールで Networking -> Virtual Cloud Networks -> 対象の VCN -> Subnets から取得します。パブリック IP が欲しいなら（欲しいはずです）パブリックサブネットを選んでください。

```bash
git clone https://github.com/lucasforster1108-boop/oracle-snatch.git
cd oracle-snatch
pip install -r requirements.txt

cp config.example.env config.env
# config.env を編集：必須なのは SUBNET_ID と SSH_PUBLIC_KEY_FILE だけ

python3 snatch.py --dry-run
python3 snatch.py
```

## 長期間走らせる

数日間無人で走らせる前提のものなので、すでに常時稼働しているマシンに置いてください（別の無料 VPS、自宅サーバー、Raspberry Pi など）。systemd サービスのサンプルも同梱しています。

```bash
sudo cp oracle-snatch.service /etc/systemd/system/
sudo systemctl enable --now oracle-snatch
tail -f snatch.log
```

## ハマったポイント

- 無料の A1 枠はインスタンスごとではなく合計です。全部で 4 コア + 24 GB。4/24 の 1 台にしても、2/12 の 2 台に分けても構いません。超えると LimitExceeded になり、スクリプトはわざと止まります。文句を言わないでください。
- アカウントを PAYG（従量課金）にアップグレードしても無料枠は消えません。枠内の A1 利用は引き続き無料で、在庫も体感では少し確保しやすくなります。私のアカウントは PAYG で、請求は今も 0、念のため予算アラートも置いています。
- ブートボリュームも無料ブロックストレージ合計 200 GB に含まれます。小さなサーバーなら 50 GB で十分です。「どうせ無料だから」と 200 を使い切らず、残りは 2 台目に回した方が得です。
- 在庫の放出は不定期で、真夜中も多いです。ループの意味はここにあります。朝 4 時に起きているのはスクリプトで、あなたである必要はありません。
- リトライ間隔を数秒まで縮めないでください。早く確保できることはなく、429 を食らってしばらく何も取れなくなります。
